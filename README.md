# 業務共有アプリ

秘書さんとオンラインで業務（物品購入・国内出張・国外出張・その他）の進み具合を共有するための Web アプリです。
ビルド不要の静的サイト（HTML / CSS / JavaScript）なので、GitHub にアップロードするだけで公開できます。

## 仕組み

- **アプリ本体**は GitHub Pages で公開します（このフォルダの中身）。
- **入力したデータと添付ファイル**は、アプリ本体とは**別のプライベートリポジトリ**に GitHub API 経由で保存します。
  そのため、仕様を追加してアプリを再アップロードしても、入力済みのデータは失われません。
- 利用者（先生・秘書さん）はそれぞれ自分の GitHub アカウントのアクセストークンをアプリの「設定」画面に登録します。トークンは各自のブラウザ内にのみ保存されます。

```
アプリ用リポジトリ（GitHub Pages で公開）      データ用リポジトリ（プライベート）
├─ index.html                               └─ data/
├─ config.js                                    ├─ settings.json   … 予算の選択肢・テンプレート
├─ css/style.css                                ├─ index.json      … プロジェクト一覧
└─ js/…                                         ├─ projects/<id>.json
                                                └─ files/<id>/…    … 添付ファイル
```

## 初回セットアップ

### 1. データ用リポジトリを作る

1. GitHub で **New repository** を開く。
2. 名前を例えば `gyomu-data` とし、**Private** を選ぶ。
3. 「Add a README file」に**チェックを入れて**作成する（空のリポジトリだと最初の書き込みに失敗することがあります）。
4. 秘書さんと共有する場合は、Settings → Collaborators から秘書さんの GitHub アカウントを **Write** 権限で追加する。

### 2. アプリ用リポジトリを作って公開する

1. 別のリポジトリ（例: `gyomu-app`）を作る。Public でも構いません（アプリ本体にはデータが含まれません）。
   Private にする場合、GitHub Pages を使うには GitHub Pro / Team などの有料プランが必要です。
2. このフォルダの中身（`index.html`, `config.js`, `css/`, `js/`, `.nojekyll`, `README.md`）をアップロードする。
   GitHub の Web 画面で「Add file → Upload files」にドラッグ＆ドロップすれば git コマンドは不要です。
3. Settings → Pages → Build and deployment で **Source: Deploy from a branch**、Branch: `main` / `/(root)` を選んで保存する。
4. 数分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` でアプリが開けます。

（任意）`config.js` にデータ用リポジトリのオーナー名とリポジトリ名を書いておくと、設定画面の初期値になります。

### 3. アクセストークンを作る（利用者ごと）

1. GitHub の右上のアイコン → Settings → 左下の **Developer settings** → **Personal access tokens** → **Fine-grained tokens** → **Generate new token**。
2. Token name: 任意（例: gyomu）。Expiration: 任意（期限が切れたら作り直して設定画面で入れ替えます）。
3. **Repository access**: 「Only select repositories」でデータ用リポジトリ（`gyomu-data`）だけを選ぶ。
4. **Permissions → Repository permissions → Contents** を **Read and write** にする（他は不要）。
5. Generate token を押し、表示されたトークン（`github_pat_...`）をコピーする（この画面を閉じると二度と表示されません）。

秘書さんも同じ手順で、自分のアカウントでトークンを作ります（コラボレーターとして Write 権限が付与されている必要があります）。

### 4. アプリに接続する

1. 公開した URL を開き、右上の「⚙ 設定」を開く。
2. オーナー、データ用リポジトリ名、ブランチ（通常 `main`）、アクセストークンを入力する。
3. 「接続テスト」で「接続できます」と表示されたら「保存して接続」を押す。
4. 設定画面の下で「予算の選択肢」を登録する（物品購入・国内出張・国外出張で共通）。必要ならチェック項目のテンプレートも編集する。

## 使い方

- 上部のタブでカテゴリ（物品購入 / 国内出張 / 国外出張 / その他）を切り替え、「新しいプロジェクト名」を入れて **作成** します。
- プロジェクトを開くと、カテゴリごとのテンプレートに沿ったタブ（例: 申請時 / 終了後）とチェック項目が並びます。
  - 入力すると自動的に保存されます（右上に「保存済み」と表示されます）。
  - 項目名はクリックして書き換えられます。↑↓ で並べ替え、× で削除、下の欄から項目を追加できます。
  - タブも「＋」で追加、名前変更、削除ができます。
  - 「メモ・連絡事項」欄は自由記入です。
- 各項目は種類ごとに完了条件が決まっており、完了すると緑のチェックが付きます。

| 種類 | 完了の条件 |
|---|---|
| チェック | チェックを入れる |
| 有 / 無 | 「有」か「無」のどちらかが選ばれている（法人カード利用など） |
| 短文入力 / 長文入力 | 何か入力されている |
| 日程（出発日・帰学日・日帰り） | 出発日があり、帰学日があるか「日帰り」がチェックされている |
| 日程（出発日・帰学日） | 出発日と帰学日の両方がある |
| 予算（選択） | 選択肢から選ばれている |
| ファイル添付 | 1つ以上ファイルがある |
| ファイル添付 または 現物提出 | ファイルがあるか「現物提出済み」がチェックされている |
| 終了 または 不要 | 「終了」か「不要」が選ばれている |

- 「✓ 完了にする」でプロジェクトを完了扱いにできます（一覧の「完了」フィルタで表示）。
- 添付ファイルはファイル名をクリックするとダウンロードされます。1ファイルあたり 50 MB までです。
- 相手の入力を反映したいときは右上の「↻ 更新」を押します（ウィンドウを切り替えて戻ったときも自動で読み直します）。

## アプリを更新するとき

アプリ用リポジトリのファイル（`index.html`, `js/…` など）を上書きアップロードするだけです。
データ用リポジトリには触らないので、入力済みの情報・添付ファイルはそのまま残ります。

## 注意事項

- お試し用に「このブラウザの中だけに保存」モードがあります。このモードでは共有されず、ブラウザのデータを消すと失われます。
- 2人が同じプロジェクトを同時に編集した場合、後から保存した側が相手の最新版を読み込み、自分が変更した項目だけを重ねて保存します。項目の追加・削除・並べ替えが重なった場合はその操作が反映されないことがあるので、画面の通知に従って確認してください。
- トークンの有効期限が切れると保存できなくなります。設定画面で新しいトークンに入れ替えてください。
- データ用リポジトリはプライベートにしてください。添付ファイルもそのリポジトリに保存されます。
